CONTENTS

                  (legacy mode reproduces EML-GP exactly), Cartesian GP and Operon wrappers, target
                  generation, the run queue (phases in src/reach/runner/phases.py) and the registered
                  analyses (src/reach/analysis/s2).
tests/            Unit, regression and guardrail tests (pytest).
scripts/          Launchers for the run phases and the registration task lists.
paper/scripts/    The paper's figure scripts (figures.py, coverage_disc.py): the five figures and the
                  graphical abstract, drawn from data/analysis and the run records (added in 1.1.0;
                  drawn at print size and reproducible byte for byte since 1.1.1).
rust/cgp/         The Cartesian GP engine (Rust).
legacy/           Verbatim copy of the EML-GP code and stored results used for the regression test.
data/targets_s2/  Every target set (calibration, held-out, benchmark and restart targets).
data/enumeration_s2/  Enumeration counts per function set and size (counts.json; level files not included).
data/registration/    The files attached to the OSF registrations and their SHA-256 lists.
data/runs/        Manifest and results (one JSON line per run) of every run phase.
data/analysis/    The outputs of every analysis, as written by the analysis code.
data/reference/   Third-party benchmark definitions with their sources and licences.
registration/     Verification against the registered versions (see below).


REPRODUCING

Python 3.9 with the pinned versions in requirements.txt (Operon needs Python 3.11 and
requirements-ext.txt; Cartesian GP needs Rust):

    python3.9 -m venv .venv && .venv/bin/pip install --upgrade pip
    .venv/bin/pip install -r requirements.txt -e .
    .venv/bin/python -m pytest

The `-e .` installs the reach package from src/ into the environment (the pip that ships with macOS's
Python 3.9 is too old for it, hence the upgrade); without it the analysis commands below and the tests that
start a subprocess cannot import the package (the in-process tests find src/ on their own).

Run records over 50 MB are stored gzipped; decompress them before an analysis:

    gunzip -k data/runs/*/*.gz

The analyses write a JSON file to data/analysis and a short report to docs/status:

    mkdir -p docs/status
    .venv/bin/python -m reach.analysis.s2.confirm        (Stage 1)
    .venv/bin/python -m reach.analysis.s2.stage2_report  (Stage 2)
    .venv/bin/python -m reach.analysis.s2.h6d_report     (Stage 3)
    .venv/bin/python -m reach.analysis.s2.h11_report     (Stage 4)

Two descriptive analyses the paper quotes write only their JSON file:

    .venv/bin/python -m reach.analysis.s2.heldout_reach  (the null read with GP's estimator; added in 1.1.0)
    .venv/bin/python -m reach.analysis.s2.baseline_auc   (the node-count baseline's AUC; added in 1.1.1)

The paper's figures (vector PDF, SVG and the graphical abstract) are drawn from data/analysis and the
run records; rsvg-convert (librsvg) is needed for the coverage disc:

    PYTHONPATH=src .venv/bin/python paper/scripts/figures.py

Rerunning the GP runs uses the run queue (python -m reach.runner run PHASE) and takes weeks of CPU.
Some phases need the enumeration level files, which are regenerated by the enumeration phases.

Tests marked study_machine need the study machine's untracked files or its exact platform, and a
few tests read the authors' private working documents; conftest.py skips both and names the reason.
Run records keep the study machine's file paths as recorded; they are covered by the OSF checksums.


VERIFYING AGAINST THE REGISTRATIONS

    python3 registration/verify_release.py

checks, by git tree hash, that the released code is the code registered at each stage, and checks
the registered files against the SHA-256 lists attached to the registrations. The code changed after
each registration; registration/src_reach_<commit>.patch holds every change from that registration
to this release and is reversed by the check before hashing.
